# IAA 三机制 Web 灰盒

一个零依赖、移动端优先的静态 Web 原型，用于比较三个适合微信/抖音小游戏的核心机制。

## 三个原型与爽点

### 1. 电梯总调度

- **压力来源**：乘客不断进入，耐心持续下降，候梯区容量有限。
- **玩家决策**：选择哪些乘客进入奇数梯或偶数梯，何时发车。
- **释放瞬间**：按楼层精准分组、满载发车，一次清空大量候梯压力并形成连调。
- **验证假设**：玩家是否会故意保留空位，等待更高价值的成组调度。

### 2. 机场行李夜班

- **压力来源**：行李持续推进，玩家必须在到达道岔前预判颜色。
- **玩家决策**：切换两级道岔，把红、蓝、黄行李送到对应登机口。
- **释放瞬间**：连续正确分流形成高速连击，整条流水线进入“顺流”。
- **验证假设**：玩家是否会提前观察后续行李，而不是只在错误发生后补救。

### 3. 消防总控

- **压力来源**：三个区域同时起火，总水压固定，风向会放大局部火势。
- **玩家决策**：从低危区域回收水压，集中到即将失控的区域。
- **释放瞬间**：建筑濒临红线时完成集中压制，火势快速归零并获得翻盘奖励。
- **验证假设**：玩家是否能理解“平均分配并非最优”，并主动进行取舍。

## 运行

直接打开 `index.html` 即可，或使用任意静态服务器：

```bash
python -m http.server 8080
```

访问 `http://localhost:8080`。

## 文件

- `index.html`：页面结构与三个原型模板
- `styles.css`：移动端优先的灰盒视觉与反馈
- `app.js`：三套独立状态机和玩法逻辑

## 推荐测试方式

找 5 名未看过说明的人，每人依次试玩三个原型。只观察：

1. 10 秒内是否理解目标；
2. 首局是否出现明显犹豫；
3. 失败后能否说出下一局怎么改；
4. 是否主动点击“再玩一次”；
5. 旁观者是否会说“别点那个 / 快切道 / 把水压移过去”。

不要先问“好不好玩”，先记录真实行为。
