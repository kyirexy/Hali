# 《凌晨四点 · 异常便利店》Web 灰盒 V2

一个面向手机竖屏（9:16）的零依赖 Web 玩法原型，用于验证比“经营 + 守门”更独立的机制闭环。

## 核心创新

### 1. 营业 / 熄灯双状态

同一个设施在两个阶段承担完全不同的功能：

- 货架：营业时提高顾客结账金额；熄灯后投掷罐头。
- 冷柜：营业时提高冷饮顾客收益；熄灯后冻结敌人。
- 监控：营业时提示可疑顾客；熄灯后标记敌人并放大伤害。
- 发电机：营业时充能证据；熄灯后释放链电。

玩家不是单纯购买炮台，而是在搭建一套会随“店铺状态”转换用途的系统。

### 2. 主动决定何时关门

营业越久，顾客越多、收入越高；但异常也可能混入。玩家可提前熄灯牺牲未到店收入，换取更可控的防守压力。

### 3. 观察判断直接改变战斗

每轮会出现一条异常识别规则。玩家需要根据顾客的影子、体温、雨伞和脚印作出拒绝或放行判断：

- 正确拒绝：增加证据、获得悬赏，并削弱最终Boss。
- 误拒普通顾客：损失声誉，后续顾客支付减少。
- 漏掉异常：它会从店内近距离偷袭卷帘门。

### 4. 跨模式空间联动

同一布局会同时影响营业和防守：

- 同排双货架形成黄金动线，提高收入。
- 货架邻接冷柜形成冷链陈列；获得改装后可变成穿透减速弹仓。
- 监控邻接发电机形成夜间供电；获得改装后可形成标记链电。

### 5. 改装不是纯数值升级

每轮结束后，从三项改装中选择一项。部分改装改变设施联动，部分提供收益与风险交换。

## 运行

直接打开 `index.html`，或运行：

```bash
python3 -m http.server 8080
```

访问 `http://localhost:8080`。

## 灰盒验证问题

1. 玩家能否在第一轮理解“按守则识别异常”？
2. 玩家是否会为了更多收入延迟关门？
3. 玩家是否理解同一设施在营业和熄灯阶段的用途变化？
4. 漏入异常后，玩家能否将门体压力归因到自己的识别错误？
5. 玩家是否愿意围绕不同改装重新组织店内布局？
